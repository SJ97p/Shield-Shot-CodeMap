# 증강을 전투의 기대감으로 만들기 위해

## 출발점: 같은 웨이브를 다시 막는 느낌을 피하고 싶었습니다

Shield & Shot에서 증강은 단순히 수치를 올리는 보상이 아니었습니다. 플레이어가 “이번에는 이 효과가 나오면 위기를 넘길 수 있겠다”고 기대하고, 같은 무기라도 매번 다른 전투를 하게 만드는 장치였습니다. 기본 화살에 분열·반사·관통·상태 이상·속성 필드가 계속 붙는 구조였기 때문에, 모든 경우를 `ProjectileBase`의 조건문으로 처리하는 방식은 오래 유지하기 어렵다고 봤습니다.

## 효과를 밖에서 주입하고, 실행 시점을 나눴습니다

투사체는 이동, 벽·환경 충돌, 적 피격을 서로 다른 순간에 처리합니다. 그래서 `IMovementBehavior`, `ICollisionBehavior`, `IHitBehavior`를 나누고 `ProjectileBehaviorSO`가 런타임 투사체에 필요한 효과를 주입하도록 구성했습니다.

```text
증강/무기 효과 선택
        ↓
ProjectileBehaviorSO
        ↓
ProjectileBase에 이동 · 충돌 · 피격 Behavior 주입
        ↓
발사 후 각 실행 시점에서 Behavior 수행
```

이 구조 덕분에 피해·넉백·상태 이상·VFX처럼 서로 다른 담당자가 만든 효과도 공통 규격으로 투사체와 대상에 연결할 수 있었습니다.

## 분열과 난반사가 남긴 회고

분열과 난반사는 순서에 따라 결과가 달랐습니다. 난반사된 화살을 분열시키는지, 분열 후 난반사를 적용하는지에 따라 자식 화살의 궤적이 달라져야 했습니다. 당시에는 `Priority`로 순서를 정하고, 자식 투사체에 특정 충돌 Behavior를 복사하지 않아 분열이 계속 전파되는 것을 막았습니다.

이는 원하는 결과를 빠르게 만들 수 있는 방법이었지만, 증강이 늘면 개발자가 기존 효과를 기억한 채 우선순위를 계속 입력해야 한다는 한계가 있습니다. 다시 만든다면 투사체나 증강이 직접 순서를 결정하기보다, 중간 판정 객체가 효과 종류와 실행 단계를 해석하도록 만들고 싶습니다.

## 코드에서 확인할 수 있는 지점

- `ProjectileBehaviorSO`: 증강 데이터와 주입 계약
- `ProjectileBase`: 이동·충돌·피격 Behavior 분리와 Priority 정렬
- `ProjectileBase.CopyBehaviorsTo`: 자식 투사체로의 특성 복사와 제외 규칙
- `ProjectileShooter`: 발사 시점의 Behavior 적용
